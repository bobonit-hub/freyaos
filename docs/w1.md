# 1-Wire

A program can drive any spare pin as a 1-Wire master: open it, reset, write,
read, and walk the ROM codes. It is polled, like I2C, at standard speed.
There is no overdrive and no slave mode. `w1` at the console opens a pin,
checks presence and walks the ROMs. Byte reads, writes and the strong
pull-up are the program calls; `samples/w1` is the thermometer.

`samples/w1` searches a pin and reads every DS18B20 and DS1822 on it. Build
it with `make` and run `run w1.bin`.

## Calls

```c
int (*w1_open)(int pin);                         /* 0, or a FREYA_ERR_* */
int (*w1_close)(int pin);
int (*w1_reset)(int pin);                        /* 0, or FREYA_ERR_NACK */
int (*w1_write)(int pin, const void *buf, int len);
int (*w1_read)(int pin, void *buf, int len);
int (*w1_search)(int pin, void *rom);            /* 8 bytes, then NACK  */
int (*w1_pullup)(int pin, int on);
int (*w1_crc)(const void *buf, int len);
```

`pin` is `FREYA_PB(12)` and the same number `pin` at the console takes.
Up to four pins may be open (`FREYA_W1_BUSES`). A transfer is at most 64
bytes (`FREYA_W1_MAX_LEN`). Opening a pin that is already open, by the same
side, does nothing.

`w1_reset()` is the presence pulse. It returns 0 when a device pulled the
line down, and `FREYA_ERR_NACK` when the line came back up on its own.
`w1_write()` and `w1_read()` do not send that pulse; a transaction is a
reset, then the bytes. Least significant bit goes first, which is the order
the bus uses, so a program hands over ordinary bytes.

`w1_search()` writes Search ROM (`0xF0`) and returns the next 8-byte ROM,
family code in the first byte. The call that follows the last device returns
`FREYA_ERR_NACK`, and the call after that starts the walk over. A ROM whose
CRC is wrong comes back as `FREYA_ERR_IO` and the walk starts over too.

`w1_pullup()` drives the pin high as a push-pull output, which is the strong
pull-up a parasite-powered device needs while it converts. The next reset,
read, write or search releases it back to open drain. `w1_crc()` is the
Dallas CRC-8. A ROM or a 9-byte scratchpad that includes its own CRC byte
returns 0. It does not touch a pin, and a handler may call it.

These calls were appended to the service table. A program built against this
header and handed an older kernel checks before it calls:

```c
if (!FREYA_API_HAS(api, w1_crc)) {
    api->puts("this kernel has no 1-Wire\r\n");
    return FREYA_EXIT_FAIL;
}
```

Reading a DS18B20 is the usual reason to open one. Skip ROM (`0xCC`) and
Convert T (`0x44`) start every device on the pin; the line is then held high
for 750 ms, which is a 12-bit conversion. Match ROM (`0x55`), the eight ROM
bytes and Read Scratchpad (`0xBE`) bring back nine bytes, and the temperature
is the first two, little endian, in sixteenths of a degree:

```c
uint8_t rom[8], skip[2] = { 0xCC, 0x44 }, tx[10], sp[9];

api->w1_open(FREYA_PB(12));
api->w1_search(FREYA_PB(12), rom);          /* one device; loop for more */

api->w1_reset(FREYA_PB(12));
api->w1_write(FREYA_PB(12), skip, 2);
api->w1_pullup(FREYA_PB(12), 1);
api->delay_ms(750);
api->w1_pullup(FREYA_PB(12), 0);

tx[0] = 0x55;
for (int i = 0; i < 8; i++) tx[1 + i] = rom[i];
tx[9] = 0xBE;
api->w1_reset(FREYA_PB(12));
api->w1_write(FREYA_PB(12), tx, 10);
api->w1_read(FREYA_PB(12), sp, 9);          /* w1_crc(sp, 9) == 0 */
api->w1_close(FREYA_PB(12));
```

Family `0x28` is a DS18B20 and family `0x22` is a DS1822. Both lay the
scratchpad out the same way. `samples/w1` is that sequence for every device
the search returns.

## Pins

Any pin of port A, B or C that Freya does not keep for the console and the
card. PA2 through PA7 are refused with `FREYA_ERR_PIN`. The same pin cannot
also be a PWM output, an SPI pin or either line of an open I2C bus: opening
one while the other still owns it returns `FREYA_ERR_BUSY`.

The line is open drain and needs a pull-up to 3.3 V. 4.7 kΩ is the ordinary
choice. The Black Pill turns on the pin's own pull-up as well, about 40 kΩ,
which will sometimes carry one device on a short run of wire and will not
carry a bus. The Blue Pill cannot turn a pull-up on for an output, so the
resistor is not optional there.

`samples/w1` uses PB12, which is free on both boards. The console takes
whatever pin the command names.

## What a slot does

The call does not return until the bits have moved. A line that is already
low, which is a missing pull-up or a short, comes back as `FREYA_ERR_TIMEOUT`
and is not pulsed. A reset that nobody answers is `FREYA_ERR_NACK`, which is
what an empty pin looks like and is not a fault.

Each slot holds interrupts off while a device is timing the line, and lets
them run again before the call returns. A write-zero is the long one, about
60 microseconds. A character that arrives at the console in that window can
be lost; the next slot is not that window.

A pin a program opened is closed when the run ends, including by Ctrl-C or a
fault, and the pin goes back to an input. A pin opened at the console stays
open, and a program that tries to open it is told the pin is taken.

The calls spin and they are not reentrant, so a handler may not make them.
The kernel returns `FREYA_ERR_HANDLER`. `w1_crc()` is arithmetic and is the
one call a handler may make.

## Errors

| | |
|---|---|
| `FREYA_ERR_PIN` | no such pin, or one the kernel keeps |
| `FREYA_ERR_BUSY` | the pin is open from the other side, already PWM, I2C or SPI, or all four buses are open |
| `FREYA_ERR_ARG` | not open, or the length is out of range |
| `FREYA_ERR_NACK` | nobody answered the reset, or the ROM walk is finished |
| `FREYA_ERR_TIMEOUT` | the line stayed low |
| `FREYA_ERR_HANDLER` | called from a handler |
| `FREYA_ERR_IO` | a ROM failed its CRC, or the run was asked to stop mid-transfer |

## At the console

`w1` with no arguments lists the open pins. Opening, presence and the ROM
walk:

```
freya: w1 PB12
PB12  1-Wire
freya: w1 PB12 search
28 aa 14 1e 0b 00 00 9a
freya: w1 PB12 reset
presence
freya: w1 PB12 off
PB12 off
```

`search` prints every ROM the walk returns. `reset` is the presence pulse.
Ctrl-C abandons a search. A pin left open here is still open after a program
runs, until `w1 <pin> off`.
